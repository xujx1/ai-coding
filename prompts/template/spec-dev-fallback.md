# 开发任务清单

## Phase 1: 代码结构与现状梳理
- [ ] 阅读 PRD、技术方案和现有项目结构，确认本次需求涉及的 Controller、Service、Mapper、DTO、领域模型和配置文件。
- [ ] 使用 `glob`、`grep`、`read_file` 定位现有同类接口、统一返回、异常处理、幂等和审计实现方式。

## Phase 2: 接口与入参实现
- [ ] 新增或修改请求 DTO，补齐需求要求的字段、校验注解和必要的访问器方法。
- [ ] 在对应 Controller 中新增接口入口，并保持现有路由、返回结构和 requestId 透传约定。

## Phase 3: 业务逻辑实现
- [ ] 在 Service 层实现需求主流程，包含参数校验、业务规则校验、状态判断、幂等处理、审计处理和成功响应。
- [ ] 按技术方案补齐错误码、异常映射和日志记录，确保失败场景可追踪。

## Phase 4: 数据访问与配置实现
- [ ] 在 Mapper/Repository 中新增或修改查询与更新方法，确保 SQL 条件、并发控制和软删除/状态过滤满足需求。
- [ ] 如需配置或 XML 变更，按项目现有风格补齐并避免影响无关链路。

## Phase 5: 编译验证与验收自查
- [ ] 运行 Maven 编译命令，修复所有编译错误。
- [ ] 对照 PRD 验收点检查接口成功、失败、幂等、审计和数据变更行为是否均已覆盖。
