# MRD: 上传需求结构化整理

## 背景
用户上传了 {{requirement_count}} 个需求文件，系统需要将其整理为后续 MRD 澄清和实施方案生成可消费的统一业务输入。

## 目标
- 汇总上传需求文件中的业务背景、功能范围、约束和验收口径。
- 明确当前已识别的项目或应用范围。
- 为后续 MRD 澄清节点提供可追溯的基础 MRD。

## 范围
### 包含范围
- 解析上传需求文件并生成结构化 MRD。
- 记录涉及项目识别结果。
- 保留需求来源摘要，便于后续澄清追溯。

### 不包含范围
- 不在 MRD 渲染阶段生成具体技术方案、代码实现或测试用例。
- 不在本阶段强行确定缺失的项目归属和接口边界。

## 业务流程
1. 用户上传需求资料和可选项目代码。
2. 系统整理需求资料为结构化 MRD。
3. 用户确认 MRD 后进入 MRD 澄清节点。
4. MRD 澄清节点补齐业务边界、异常路径、字段口径和验收标准。

## 约束
- 当前 MRD 来源于上传文件摘要，超大文件只截取前段内容作为兜底摘要。
- 后续节点应读取 `artifacts/mrd.md` 和 source map，不依赖 Agent transcript。
- 若未上传项目代码，后续需要用户确认目标应用或补充项目目录。

## 验收标准
1. `artifacts/mrd.md` 存在且包含结构化 MRD 章节。
2. MRD 包含项目识别结果，即使结果为“未检测到上传项目”。
3. `artifacts/mrd-source-map.json` 可追溯到上传需求文件。
4. 用户确认后可继续进入 MRD 澄清节点。
