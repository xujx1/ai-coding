```markdown
# 活动命中预览 MRD

## 1. 背景

当前营销管理台已经支持运营人员创建活动、配置活动玩法并关联商品或 SKU。活动配置完成后，运营人员通常需要确认某个商品在指定区域下是否真的能够命中目标活动，否则容易在上线后才发现范围配置错误、SKU 漏绑、Region 选错、活动状态不符合预期或同步结果异常。

现有流程缺少一个面向运营的“发布前检查”和“上线后校验”入口。运营人员只能通过接口返回、数据库或测试订单间接判断活动是否生效，排查成本较高，也容易把配置问题带到正式流量中。

## 2. 目标

为营销活动增加命中预览能力，让运营人员可以在配置活动后，用商品、SKU、区域等业务条件快速判断活动是否可命中，并看到清晰的命中结果或未命中原因。

本需求希望达到以下业务目标：

- 降低活动上线前的配置校验成本。
- 帮助运营快速发现商品范围、SKU、Region、活动状态等配置问题。
- 支持上线后确认用户侧运行结果是否符合预期。
- 减少因活动误配导致的客诉、资损或临时下线。

## 3. 业务范围

### 3.1 本期包含

- 在营销管理台提供活动命中预览入口。
- 支持运营输入商品、SKU、活动范围、区域等条件发起预览。
- 支持展示命中的活动列表。
- 支持展示活动的核心信息，包括活动 ID、玩法类型、状态、优惠门槛和优惠值。
- 支持未命中时展示可理解的业务提示。
- 支持运营区分“管理配置侧结果”和“用户运行侧结果”。

### 3.2 本期不包含

- 不新增活动创建、审批、上线、下线等生命周期能力。
- 不实现完整订单价格计算。
- 不处理多个活动之间的叠加、互斥和最优优惠选择。
- 不新增复杂权限体系。
- 不新增批量预览能力。
- 不新增活动配置自动修复能力。

## 4. 用户故事

### 4.1 发布前检查

作为运营人员，我希望在活动配置完成后输入一个商品或 SKU，快速确认该商品是否能命中我刚配置的活动，以便在提交审批或上线前发现配置错误。

### 4.2 上线后校验

作为运营人员，我希望活动上线后再次用相同商品或 SKU 校验用户侧是否已经能命中活动，以便确认活动已经同步并生效。

### 4.3 未命中排查

作为运营人员，当预览结果没有命中活动时，我希望系统给出清晰提示，例如可能是商品未绑定、SKU 不匹配、区域不一致、活动未上线或同步尚未完成，而不是只看到空结果。

### 4.4 配置对比

作为运营人员，我希望能看到管理配置侧和用户运行侧的结果差异，以便判断问题发生在活动配置阶段，还是发生在上线同步或用户侧运行阶段。

## 5. 业务规则

### 5.1 预览条件

活动命中预览至少需要支持以下业务条件：

- 区域：例如 `CN`、`US`。
- 活动范围类型：例如全场、类目、商品、SKU。
- 商品 ID。
- SKU ID。
- 操作人。

当 SKU ID 为空时，系统按商品维度进行预览。当 SKU ID 不为空时，系统优先按 SKU 维度进行预览。

### 5.2 命中结果

命中结果需要展示运营判断活动是否正确生效所需的核心信息：

- 活动 ID。
- 活动名称或可识别活动的字段。
- 活动状态。
- 玩法类型。
- 优惠门槛。
- 优惠金额、折扣或券模板信息。
- 区域。
- 商品或 SKU 命中条件。

### 5.3 未命中结果

未命中不应被视为系统异常。系统需要展示空状态，并给出业务排查方向：

- 当前商品或 SKU 没有关联活动。
- 当前区域下没有可命中的活动。
- 活动尚未上线或不在有效期内。
- 活动配置已存在，但用户侧可能尚未同步完成。

### 5.4 管理配置侧结果

管理配置侧结果用于帮助运营确认“活动配置是否正确”。它更关注活动配置、商品绑定和区域范围是否符合预期。

### 5.5 用户运行侧结果

用户运行侧结果用于帮助运营确认“用户实际请求是否能命中活动”。它更关注活动上线后在用户侧是否已经生效。

如果管理配置侧有结果，但用户运行侧无结果，系统应提示可能存在同步延迟、活动未上线或用户侧数据尚未生效。

如果管理配置侧和用户运行侧都无结果，系统应提示优先检查活动范围、商品绑定和区域配置。

## 6. 验收口径

- 运营可以在营销管理台发起单个商品或 SKU 的命中预览。
- 预览结果可以区分管理配置侧和用户运行侧。
- 命中时，运营可以看到活动 ID、活动状态、玩法类型和优惠核心信息。
- 未命中时，页面展示空状态和业务排查提示。
- 管理配置侧有结果、用户运行侧无结果时，页面能提示可能存在同步或上线状态问题。
- 非法或缺失的必要输入能被拦截并提示运营修正。
- 本需求不要求给出最终订单实付金额。

## 7. 约束与假设

- 本需求服务于运营配置校验，不替代真实下单链路。
- 活动最终是否可用仍以用户侧正式交易链路为准。
- 本期只支持单商品或单 SKU 预览。
- 多活动优先级、优惠叠加和最终价格计算由后续需求处理。
- 管理配置侧和用户运行侧可能存在短暂不一致，页面需要把这种差异解释为可排查状态，而不是直接归类为系统错误。

```
