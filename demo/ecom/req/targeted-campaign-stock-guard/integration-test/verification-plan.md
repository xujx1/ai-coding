# 验证计划

## 一、执行顺序

1. 检查 `ecom-product`、`ecom-inventory`、`ecom-marketing`、`ecom-trade`、`ecom-console` 是否可用。
2. 执行商品与库存 seed SQL。
3. 执行 IT-01 到 IT-04 的 API 校验。
4. 执行 IT-05 控制台人工校验。
5. 执行 IT-06 交易回归。
6. 按逆序执行 cleanup SQL 和 API 清理。

## 二、前提

| 项目 | 要求 |
|------|------|
| 环境 | `review-only` 不执行真实 SQL；如要实跑，切换到 `integration` 并提供环境配置 |
| 服务 | 商品、库存、营销、交易服务可访问；控制台静态页面可打开 |
| 隔离键 | 所有数据使用 `campaign-stock-guard-it-20260716` 前缀 |

## 三、观测点

| 验证点 | 预期 |
|--------|------|
| 创建活动 | 只校验，不保护库存 |
| 启用活动 | 生成保护记录 |
| 删除活动 | 释放保护记录，重复调用幂等成功 |
| 控制台 | 展示每一步请求和返回 |
| 交易回归 | 不出现营销保护相关异常 |

## 四、清理顺序

1. 删除营销活动。
2. 释放库存保护记录。
3. 删除库存测试行。
4. 删除商品测试行。
5. 清理交易演示订单。

## 五、阻塞项

| 阻塞项 | 说明 |
|--------|------|
| 未提供 `execute=true` | 当前仅生成脚本与计划，不执行真实集成测试 |
| 未提供 `environment_config_path` | 无法调度真实环境准备和执行器 |
