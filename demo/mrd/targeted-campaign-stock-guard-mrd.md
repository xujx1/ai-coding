# MRD: 定向营销活动创建时增加商品上架与库存保护校验

## 1. 需求背景

当前运营在 console 中可以分别完成商品上架、营销活动新建/启用/删除、下单演示等动作，但营销活动创建阶段只校验活动自身字段，缺少对商品状态和库存可售能力的前置校验。

这会导致运营创建并启用活动后，用户在交易链路才发现商品未上架、库存不足或库存不可预占，形成活动已露出但无法承接转化的问题。对秒杀、满减、定向券等库存敏感活动尤其明显。

本需求希望在营销活动创建和启用前，增加商品上架状态与库存保护校验，并在 console 中给运营明确反馈。

## 2. 业务目标

1. 运营创建营销活动时，系统能校验活动关联 SKU 是否已上架。
2. 运营启用营销活动时，系统能校验 SKU 是否有足够可用库存支撑活动预算。
3. console 提供一个“创建受库存保护的活动”入口，能展示商品、库存、活动三个域的校验结果。
4. 活动删除时释放活动库存保护标记，避免库存长期被活动占用。

## 3. 影响应用范围

| 应用 | 角色 | 预计改动 |
|------|------|---------|
| `console` | 运营入口 | 增加库存保护活动创建按钮/表单结果展示，串联商品、营销、库存接口 |
| `ecom-marketing` | 主应用 | 新增活动创建/启用前置校验，保存活动的库存保护信息 |
| `ecom-product` | 上游校验应用 | 提供 SKU 上架状态查询或复用现有商品信息能力 |
| `ecom-inventory` | 上游校验应用 | 提供 SKU 可用库存查询和活动库存保护/释放能力 |

不纳入本次变更的应用：

- `ecom-trade`：交易下单链路保持现状，只作为后续回归验证对象。
- `ecom-payment`、`ecom-fulfillment`、`ecom-logistics`：不做代码改动。
- `ecom-user`：本次不做用户定向人群能力，仅预留活动扩展字段。

## 4. 需求规模

预估工作量：约 5 人日。

拆分建议：

| 工作项 | 应用 | 预估 |
|--------|------|------|

## 5. 核心用户故事

### 用户故事一：运营创建库存保护活动

作为运营，我希望在创建营销活动时输入 SKU、活动库存预算、优惠金额和活动名称，系统自动检查 SKU 是否已上架、库存是否足够，这样我可以避免创建无法售卖的活动。

### 用户故事二：运营启用活动前获得明确失败原因

作为运营，我希望活动启用失败时看到具体失败原因，例如“SKU 未上架”或“可用库存不足”，而不是只看到通用失败。

### 用户故事三：运营删除活动后释放库存保护

作为运营，我希望删除活动后，系统自动释放该活动占用的库存保护，避免后续活动或交易被错误拦截。

## 6. 业务流程

### 6.1 创建库存保护活动

1. 运营在 console 输入活动信息：`campaignId`、`name`、`skuId`、`discountCent`、`quota`、`protectedStock`。
2. console 调用营销域创建库存保护活动接口。
3. 营销域调用商品域查询 SKU 状态。
4. 商品域返回 SKU 是否存在、是否已上架、基础价格等信息。
5. 营销域调用库存域查询 SKU 可用库存。
6. 库存域返回可用库存、已预占库存、可保护库存。
7. 当 SKU 已上架且可用库存不少于 `protectedStock` 时，营销域保存活动并记录库存保护需求。
8. console 展示创建成功，并显示商品校验、库存校验、活动状态。

### 6.2 启用库存保护活动

1. 运营点击启用活动。
2. 营销域再次校验活动关联 SKU 的上架状态。
3. 营销域请求库存域为活动保护库存。
4. 库存域按 `campaignId + skuId` 幂等创建活动库存保护记录。
5. 营销域将活动状态改为 enabled。
6. console 展示启用成功。

### 6.3 删除库存保护活动

1. 运营点击删除活动。
2. 营销域将活动置为 deleted。
3. 营销域调用库存域释放 `campaignId + skuId` 对应的活动库存保护。
4. console 展示删除成功和释放结果。

## 7. 功能需求

### 7.1 console

1. 新增按钮：`创建库存保护活动`。
2. 操作请求默认参数可使用演示数据：
   - `campaignId`: `CAMP-STOCK-GUARD-1`
   - `skuId`: `SKU-DEMO-1`
   - `protectedStock`: `20`
   - `discountCent`: `1000`
   - `quota`: `100`
3. 页面结果区域展示：
   - 商品校验结果：SKU 是否存在、是否上架。
   - 库存校验结果：可用库存、保护库存、是否通过。
   - 活动结果：活动状态、失败原因。
4. 失败时不吞掉错误，要展示接口返回的 `message` 或 `reason`。

### 7.2 ecom-marketing

1. 新增或扩展活动创建接口，支持库存保护字段：
   - `campaignId`
   - `skuId`
   - `protectedStock`
   - `discountCent`
   - `quota`
2. 创建活动时校验：
   - SKU 必须存在。
   - SKU 必须已上架。
   - `protectedStock` 必须大于 0。
   - 可用库存必须大于等于 `protectedStock`。
3. 启用活动时执行库存保护：
   - 使用 `campaignId + skuId` 做幂等键。
   - 重复启用不能重复扣减或重复保护库存。
4. 删除活动时释放库存保护：
   - 活动不存在时返回明确错误。
   - 活动已删除时重复删除应返回幂等成功或明确已删除状态。
5. 活动结果需要返回商品校验和库存校验摘要，供 console 展示。

### 7.3 ecom-product

1. 提供 SKU 售卖状态查询能力，供营销域调用。
2. 返回字段至少包括：
   - `skuId`
   - `spuId`
   - `title`
   - `saleable`
   - `status`
   - `priceCent`
3. 当 SKU 不存在时返回明确错误。
4. 当 SKU 未上架时返回 `saleable=false` 或等价业务状态。

### 7.4 ecom-inventory

1. 提供 SKU 可用库存查询能力。
2. 提供活动库存保护能力：
   - 输入 `campaignId`、`skuId`、`protectedStock`。
   - 校验可用库存是否足够。
   - 使用 `campaignId + skuId` 幂等。
3. 提供活动库存保护释放能力：
   - 输入 `campaignId`、`skuId`。
   - 重复释放不能导致库存异常增加。
4. 返回字段至少包括：
   - `skuId`
   - `availableStock`
   - `reservedStock`
   - `protectedStock`
   - `passed`
   - `reason`

## 8. 非功能需求

1. 接口失败要返回可读错误，便于 console 和 ai-testing 断言。
2. 库存保护必须幂等，不能因重复启用活动导致重复占用库存。
3. 删除活动后的库存释放也必须幂等。
4. 本需求不要求引入真实 MQ，优先同步接口调用即可。
5. 本需求不要求接入真实用户人群定向。

## 9. 验收标准

### 9.1 正向场景

1. 给定 SKU 已创建并已上架，库存可用数量为 100。
2. 当运营创建 `protectedStock=20` 的营销活动。
3. 则活动创建成功，返回商品校验通过、库存校验通过。
4. 当运营启用活动。
5. 则库存域产生活动库存保护记录，活动状态为 enabled。
6. 当运营删除活动。
7. 则库存保护被释放，活动状态为 deleted。

### 9.2 商品未上架场景

1. 给定 SKU 存在但 `saleable=false`。
2. 当运营创建库存保护活动。
3. 则创建失败。
4. console 展示失败原因：SKU 未上架或商品不可售。
5. 库存域不产生保护记录。

### 9.3 库存不足场景

1. 给定 SKU 已上架，但可用库存小于 `protectedStock`。
2. 当运营创建或启用库存保护活动。
3. 则操作失败。
4. console 展示失败原因：库存不足。
5. 营销活动不能进入 enabled 状态。

### 9.4 幂等场景

1. 给定活动已经启用并保护库存 20。
2. 当重复启用同一活动。
3. 则库存保护数量不重复增加。
4. 返回结果应说明已保护或幂等成功。

## 10. ai-testing 造数要求

### 10.1 基础数据

需要准备：

| 数据 | 应用 | 说明 |
|------|------|------|
| SKU | `ecom-product` | `SKU-DEMO-1`，已上架，价格 9900 |
| 库存 | `ecom-inventory` | `SKU-DEMO-1` 可用库存不少于 100 |
| 活动 | `ecom-marketing` | `CAMP-STOCK-GUARD-1`，保护库存 20 |

### 10.2 建议测试流程

1. 调用商品域创建 SKU 并上架。
2. 调用库存域初始化或调整 SKU 可用库存。
3. 调用营销域创建库存保护活动。
4. 调用营销域启用活动。
5. 查询库存域保护记录或库存摘要。
6. 调用营销域删除活动。
7. 查询库存域确认保护库存释放。

### 10.3 清理规则

1. 测试数据统一使用 `CAMP-STOCK-GUARD-*`、`SKU-DEMO-*` 前缀。
2. 每次测试完成后删除活动并释放库存保护。
3. 如测试失败，清理流程可重复执行，不应造成库存异常。

## 11. 风险与待确认

1. 当前库存域是否已有直接调整库存的测试接口需要 fanout 后确认。
2. 商品域现有 `/business/enable-sale` 能否返回足够的 SKU 状态信息需要确认。
3. 营销域活动状态模型是否已有 protectedStock 字段需要技术方案确认。
4. console 是静态页面，是否需要新增复杂表单还是沿用按钮演示方式需要确认。

## 12. 非目标

1. 不做真实用户人群定向。
2. 不做复杂促销叠加规则。
3. 不做交易链路库存扣减改造。
4. 不引入 MQ、任务调度或异步补偿。
5. 不接入真实支付、物流、履约。
